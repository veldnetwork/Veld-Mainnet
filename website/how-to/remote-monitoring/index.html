Set up remote monitoring

Pair Veld Node with the secure portal, understand exactly what the portal can see and control, and disable remote access when it is no longer needed.

Open monitoring portalAbout 7 minutes

01 / Enable

Turn on remote access deliberately

In Veld Node, open Settings → Remote access and enable the toggle. The app creates a protected device credential and begins connecting to portal.veld.network over HTTPS.

Enabling this sends operational health data off the computer. Leave it disabled if you do not want remote status or remote operations.

Health data reported

  • Device name and installed Veld version.
  • Height, sync lag, chain-data size, mempool size, and last-block age.
  • Hashrate, worker count, mining state, session hashes, and mined-block count.
  • Peer totals, inbound/outbound counts, peer roles, exact-tip count, and anonymized topology.
  • Selected sync, Tor, reachability, public-reference, and mining preferences.

Wallet keyfiles, private keys, and passphrases are not part of the monitoring report.

02 / Pair

Use the one-time code

  1. Wait for the pair code

    Settings displays a temporary code in the format ABCD-EFGH and the message Open the portal and enter the one-time code.

  2. Open the official portal

    Use the app’s Open portal button or enter the exact HTTPS address yourself.

    https://portal.veld.network/

  3. Enter the code once

    Use Copy code or type it into the signed-in portal. Do not post the code publicly or send it to another person.

  4. Confirm the app reports Connected

    Veld Node should show Connected. Remote operations are active.

Treat the pair code as temporary access authority. Anyone who can use it before expiration may be able to attach the device to a portal account.

To move the node to another account, use Settings → Remote access → New pair code locally and confirm revocation of the old pairing. For account creation, the 15-minute code lifecycle, and pairing troubleshooting, use Pair Veld Node with the Portal.

03 / Control

Understand what pairing authorizes

A paired portal is not view-only, but it is not unattended remote control. It requests restricted, signed, time-limited commands. Every command requires a Yes approval in Veld Node on the paired computer, including the first command that establishes trust in a new pairing. Without local approval, no action is performed.

Node
Start or stop the app-managed node process.
Mining
Save CPU-mining and worker-count preferences for the next app-managed start; do not assume the running workers changed immediately.
Network
Change Tor-only preference, inbound-reachability preference, and public-reference display.
Synchronization
Request Full IBD for the next start while the node is stopped. In the current Windows client, choose Signed snapshot locally on the Blockchain page; a Portal snapshot button is not proof that the command is supported or applied.
Updates
Check for or install a signed update through the normal authenticated updater.
  • Protect the portal account with a unique password and its strongest available sign-in protection.
  • Review remote commands before using them on an actively mining node.
  • Expect some setting changes to require a stopped node or a next-start cycle.
  • Confirm command results in the local Veld Node interface.

04 / Disable

Turn access off when finished

  1. Disable Remote access in Settings

    Turn off the toggle on the node itself.

  2. Confirm the local status

    The app should report Remote access disabled. Portal reporting and command polling stop. Ordinary peer traffic and separately enabled public-reference requests are not disabled by this toggle.

  3. Review the portal device list

    Remove or revoke the device there as well if the portal account should no longer retain the pairing.

Disable locally after account loss or suspected compromise. Do not wait for remote access to be restored before stopping the report and command channel.

Troubleshooting

The portal is unavailable

Veld Node reports the failure and retries automatically. Local node, wallet, mining, and validation functions continue independently.

The code expired

Keep Remote access enabled and wait for a current code, then enter that code in the official portal.

The portal shows stale status

Confirm the node still reports Connected, check ordinary HTTPS connectivity, and verify the local clock.
