How-to / Mining

Start CPU mining

Protect the mining identity, select a worker profile that fits the computer, and verify that the node is producing real VeldHash work.

Veld Node · About 8 minutes
01Identity02Configure03Start04Verify

01 / Identity

Create or import the mining identity

Stop the node before changing identity files. In Settings → Local paths, use one of the supported actions.

Create identity
Generates a new protected mining identity when miner.key does not already exist.
Import keyfile
Imports an encrypted Veld .veld-keys wallet file into the node’s identity flow.
  • Use a strong passphrase and keep it separate from the identity file.
  • Record the mining address shown by the app.
  • Select Open data folder and back up the encrypted identity before mining funds accumulate. Successful sign-in creates or verifies the matching .veld-keys file beside miner.key; repeated logins reuse it. The same file and passphrase work in the wallet and node.
  • Never run two nodes from the same data folder at the same time.
Identity changes are disabled while the node runs. Stop it cleanly, make the change in Settings, and then use the app-managed start.

02 / Configure

Choose CPU capacity

In Settings, turn on CPU mining and choose a worker profile. The worker count controls how many CPU threads VeldHash uses.

Eco
Uses one quarter of the detected physical cores, rounded up.
Balanced
Uses three quarters of the detected physical cores, rounded up.
Max
Uses one worker per detected physical core.
Custom
Select 1–64 workers. A worker is a CPU thread; custom counts can use more than one thread per physical core.

The initial default reserves one physical core where possible. Presets and custom counts are settings, not an automatic benchmark. Worker changes apply at the next app-managed start.

Compare steady hashrate after startup and dataset preparation at several nearby worker counts. More threads can reduce performance when memory bandwidth or cooling is the limit. Keep the fastest stable setting that leaves the computer responsive.

Start conservatively. Veld Node reports real hashrate and worker activity, but it does not invent temperature, fan, or power readings that the operating system does not provide.

03 / Start

Start the node and let admission checks finish

Use the app’s start control. Mining begins only after the chain and network satisfy the node’s safety checks.

Synchronizing

The local chain is not fully validated yet.

Waiting for peer tip

Fresh canonical peer-tip confirmation is required.

Propagation

Mining is paused until the current tip is acknowledged.

Hashing

VeldHash workers are advancing current canonical work.

Other safe waiting states can report clock drift, unavailable anchors, a peer-floor requirement, or a derived-state rebuild. Read the detail shown on the Mining page before changing settings.

04 / Verify

Confirm real mining activity

Open the Mining page and verify the telemetry itself—not merely that a process exists.

  • Mining status reads Hashing.
  • Total hashrate is nonzero and changes over time.
  • CPU workers matches the selected profile or custom count.
  • Hashes this session increases.
  • Chain is Validated and Peers is Connected.
  • The displayed miner address is the backed-up identity you expect.
A running process is not proof of mining. Hashrate, worker count, advancing hash totals, synchronized chain state, and connected peers are the meaningful checks.

Mining on several computers

Run one client and a separate data folder on each computer. Version 3.1.0 gives each mining process its own search origin, including when computers use the same payout address. Tune workers on each computer independently and pair each machine through + Add machine in the Portal. The Portal monitors the machines; it does not combine them into a mining pool.

Mainnet rewards and timing

The target block interval is approximately 180 seconds, not a guaranteed wait. Ordinary blocks pay 50% of the subsidy directly to the winning miner; every 100th block sends its subsidy to the vault instead. Staking is now active: the remaining ordinary-block subsidy is allocated 20% to the co-mining pool, 20% to the vault, and 10% to the endorsement pool. The co-mining draw runs every 100 blocks; the vault distribution schedule runs every 480 blocks. Running a miner does not guarantee finding a block.

If mining does not start

Mining status says Node only

CPU mining is disabled. Stop the node if necessary, enable CPU mining in Settings, select workers, and start it again.

Mining stays on Synchronizing

Complete chain validation first. Use the Blockchain page to follow local height and sync status.

The Mining page reports an error

Open Logs, use Copy diagnostics, and review the newest node-reported error without sharing wallet files or passphrases.

Add co-mining lottery eligibility

Staking and co-mining are active. Keep at least 1,000 VELD staked under the same address your miner uses, and let the client submit qualifying near-miss work. Read Stake VELD: co-mining eligibility for the requirements and 100-block draw windows. The full staking guide covers wallet setup, lockups, and unstaking.
