How-to / Network

Choose Clearnet or Tor-only networking

Understand what each transport changes, choose whether to attempt inbound reachability, and verify the mode after the next node start.

Privacy guide · About 6 minutes
01Compare02Choose03Verify

01 / Compare

Decide which tradeoff fits

Clearnet
The default. Veld connects directly to peers, so those peers can see the node’s public IP. It normally connects faster and can accept inbound P2P traffic when the network permits it.
Tor-only
Routes Veld peer traffic through Tor to reduce direct IP exposure. Inbound clearnet mapping is disabled while this mode is selected.
Clearnet outbound only
Uses direct outbound connections without requesting a router mapping. The node can validate, relay, and mine with outbound peers.
Tor-only covers Veld peer traffic. It is not a device-wide VPN and does not route unrelated browser or operating-system traffic through Tor. The node disables direct HTTPS snapshot downloads in this mode and synchronizes through Tor peers.

02 / Choose

Save the next-start preference

  1. Stop the node

    Transport controls are intentionally unavailable while the process runs. Stop it cleanly from Veld Node.

  2. Open Settings

    Use Tor-only privacy to choose the peer transport. Clearnet remains the default when this option is off.

  3. Choose inbound reachability for Clearnet

    If Tor-only is off, Attempt inbound reachability asks the router for a NAT-PMP, PCP, or UPnP mapping on the next start. If mapping is unavailable, the node continues safely with outbound peers.

  4. Start the node again

    The saved preferences apply to the next app-managed start. Tor preparation may take additional time on first use. Open Veld Node.exe directly to retain that preference: Start Veld Node.bat explicitly chooses Clearnet.

Never expose RPC or local wallet ports. Clearnet reachability concerns P2P TCP 8333. RPC 8334 and the local wallet and explorer remain local-only.

03 / Verify

Confirm the active transport

Open the Network page and read the Transport field after peers connect.

Tor only

Peer traffic is using the Tor transport.

Clearnet · automatic mapping

The router mapping request succeeded.

Clearnet · inbound verified

An inbound clearnet peer has confirmed reachability.

Clearnet · awaiting inbound

Reachability was requested, but no inbound peer has confirmed it yet.

Clearnet · outbound only

The node is operating with outbound peers and no verified inbound path.

  • Direct peer count is nonzero.
  • The displayed transport matches the saved preference.
  • Chain height begins advancing or remains at the exact tip.
  • Mining work admission sees connected peers if mining is enabled.

Common questions

Do I need inbound peers to mine?

No. A node with healthy outbound peers can validate and mine. Inbound reachability improves network connectivity but is not required for normal operation.

Why can’t I change Tor while the node runs?

The app binds transport configuration to an app-managed process start so peer sockets cannot silently change underneath a running node.

Tor preparation failed

Review the local app log. You can stop the node, select Clearnet, and start again while investigating Tor setup.
