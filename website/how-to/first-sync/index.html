How-to / Veld Node

Understand your first synchronization

Follow the local validation state, understand full IBD and eligible recovery, and wait for the node—not a public website—to declare synchronization complete.

Node guide · About 6 minutes
01Start02Read03Choose04Complete

01 / Start

Let the node open its local chain state

Start Veld Node and open the Blockchain page. A new installation first opens the local database, connects to peers, and begins downloading and validating blocks.

Ready to start

The node process is stopped.

Opening chain state

The process is running but local status is not ready yet.

Downloading and validating

Blocks are arriving and being checked.

Synchronized

The local validated height has reached the current target.

Do not close the app because the first percentage moves slowly. Initial validation is disk- and CPU-intensive and can progress unevenly.

02 / Read

Understand the Blockchain page

Local height
The highest block this node has validated.
Network reference
A public estimate used only to draw visual progress. It is never a consensus or security input.
Remaining
The estimated block difference between local validation and the displayed reference.
Peer sources
Direct peers currently available to provide and confirm chain data.
Local data
The verified chain data stored in the client’s veld-data directory.

The progress estimate may change as the public reference advances. The node’s own validated state remains authoritative.

03 / Choose

Use the supported synchronization mode

Full IBD
Validates every block from genesis on first use. This remains an explicit choice. Later starts can reuse authenticated local validation receipts and verify newer work while replaying consensus state.
Signed snapshot
Selectable on fresh mainnet installations as well as updates. The node only imports an official, authenticated, compatible snapshot newer than the local chain. Imported state is replayed and remains quarantined until a separate genesis IBD matches the exact tip and state digest.
  • Select Full IBD or Signed snapshot on the Blockchain page. A selection made while running applies on the next start.
  • Selected is a preference, not proof that a snapshot was imported or validated. Check Logs and the node-reported state.
  • A missing, invalid, incompatible, or unnecessary snapshot falls back to ordinary peer synchronization. Never bypass a validation failure.
  • Tor-only disables HTTPS snapshot downloads and synchronizes through Tor peers.
  • An update alone does not erase the same mainnet installation's chain, identity, or valid receipts. Preserve the data folder. A mandatory migration or validation requirement still takes precedence.
  • Never download and install an unofficial chain-state folder.
A snapshot does not bypass validation. The node’s RPC, inbound peers, mining, validator signing, and local explorer remain locked until independent genesis verification succeeds. The public wallet website is a separate service. After a new snapshot is verified, the client records the result and restarts once to enable services. A receipt-backed restart can reuse verified work; normal peer synchronization must still complete.

04 / Complete

Know when the node is ready

Follow Blockchain progress, then confirm the Overview, Network, and Mining pages agree with the local node. The displayed Synchronized progress estimate alone does not prove that snapshot quarantine or mining admission has finished.

  • The local node is online.
  • At least one peer is connected.
  • The local height is at the current target.
  • The exact-tip peer check is current.
  • Independent snapshot validation has completed, if a snapshot was imported.
  • Mining reports Hashing when CPU mining is enabled and all admission checks pass.
Process activity alone is not completion. CPU usage, memory use, or a running executable does not prove that the chain is synchronized.

If progress appears stuck

No peers are connected

Open the Network page, wait for initial discovery, and follow the no-peers troubleshooting guide if the count remains zero.

The public reference is unavailable

The node can still validate from peers. The reference is display-only and can be disabled in Settings.

Mining says Synchronizing

This is expected until the local chain is fully validated. Do not repeatedly restart the app; let synchronization finish.
