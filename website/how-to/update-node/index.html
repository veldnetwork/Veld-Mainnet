How-to / Maintenance

Update Veld Node safely

Use the built-in signed release flow so the node stops cleanly, authenticates every replacement, installs atomically, and retains rollback protection.

Maintenance · About 5 minutes
01Prepare02Check03Install04Confirm

01 / Prepare

Protect the identity before maintenance

Updates are designed to leave wallet material alone, but every maintained node should have a verified identity backup.

  • Open Settings → Local paths → Open data folder.
  • Confirm the encrypted miner.key and matching portable .veld-keys file are backed up. Current clients create a missing portable file after successful sign-in to a legacy encrypted mining identity; they do not create a different wallet.
  • Keep the passphrase separate from the file.
  • Finish any wallet action before starting the update.
  • Do not launch a second node from the same folder.
Wallet secrets never enter the updater. The update path works on signed release files and the app-managed node process, not on the private key.

02 / Check

Verify the signed release feed

  1. Open Settings

    Find Release and updates. The installed version is shown in this section.

  2. Select Check now

    The app checks the signed release feed without stopping the running node.

  3. Read the result

    Latest signed release verified means no newer authenticated version is available. Signed update available enables the install action.

  4. Review the changelog

    Select View changelog before installing so behavior or operational changes are not a surprise.

“Signed feed could not be verified” is a stop condition. Retry later; do not replace files manually from an unverified download.

03 / Install

Let the app perform the replacement

  1. Select Update now

    The app first asks the exact packaged node process to stop cleanly. If it cannot stop safely, installation does not begin.

  2. Wait through verification

    The updater downloads the candidate release, verifies the pinned ML-DSA-65 signature and exact signed hashes, rejects extra or missing files, and enforces strict version ordering.

  3. Allow the atomic install to finish

    Replacement is staged before activation and keeps rollback material. Do not move, rename, or edit the client folder during this phase.

  4. Let Veld Node restart

    On success the app reports Signed update ready · restarting and reopens from the installed release.

A failed update should fail safely. If the app reports Update failed safely, leave the installation intact, restart Veld Node if needed, and retry after checking connectivity and Logs.

04 / Confirm

Verify the restarted node

  • Release and updates shows the expected installed version.
  • Overview reports the local node online.
  • Blockchain opens the existing mainnet data folder, not an empty new one.
  • The saved Full IBD or Signed snapshot preference is retained. An update alone does not require deleting chain data or repeating a full download; mandatory migration or validation requirements still apply.
  • A reused receipt must still match the chain and identity. A newly imported snapshot stays quarantined until independent genesis validation succeeds.
  • Network peers reconnect.
  • The expected mining identity and address remain selected.
  • Mining returns to its valid state after synchronization and peer checks.

Run Check now once more. The result should report the latest signed release as verified.

Updater protections

Signature required
A missing, malformed, or invalid release signature is rejected.
Exact manifest
Shipping files must match the signed list and hashes.
No downgrade
An older signed version cannot replace the installed version.
No same-version swap
A same-version manifest with a different node hash is rejected.
Atomic replacement
Files are staged and installed with rollback protection rather than overwritten piecemeal.
